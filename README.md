# Laboratory Submissions

Each laboratory is organized into its respective folder. Individual submissions are maintained separately wherever applicable.

## Lab 1 – Requirements Engineering and UML Use-Case Modelling

Individual submissions covering requirements engineering, functional and non-functional requirements, and use-case modelling for the assigned problem statements.

## Lab 2 – Project Planning and Agile Development

Individual submissions documenting project planning and Agile development activities, including epics, user stories, story points, and sprint planning.

## Lab 3 – UML Component Modelling

Individual submissions presenting component architecture, system components, interactions, and interfaces for the assigned use cases.

## Lab 4 – Vibe Coding

Individual Vibe Coding assignments involving AI-assisted software development, implementation, debugging, and improvement of assigned starter projects.

Submissions include source code, project-specific README files, requirements, before-and-after demonstrations, and AI interaction histories where available.

## Lab 5 – Software Quality, Static Analysis and Code Improvement

Individual submissions involving software quality assessment, code analysis, identification of code issues, and improvements to the assigned programs.

Submissions include:
- Original and improved source code.
- Pylint and Flake8 analysis reports.
- Bandit security analysis reports.
- Issue documentation.
- Reflection documents.
- Individual lab reports.

## Lab 6 – Software Testing and Code Coverage

Individual submissions focusing on software testing, test-case development, code coverage, and branch coverage for the assigned problem statements.

Submissions include:
- Application source code.
- Code coverage test files.
- Branch coverage test files.
- Test cases.
- Coverage screenshots and supporting documentation.

## Lab 7 – Fuzz Testing with Hypothesis

Individual submissions implementing property-based and fuzz testing using the Hypothesis framework.

The assignments focus on generating diverse inputs, testing function behaviour, identifying unexpected exceptions, and validating expected properties.

Submissions include:
- Defensive implementations of assigned functions.
- Hypothesis-based fuzz tests.
- Property-based tests.
- Python dependency requirements.
- Test execution evidence and screenshots.

# Team Mini-Project

## Healthcare Appointment and Patient Record Manager

The team mini-project is a Healthcare Appointment and Patient Record Manager application developed collaboratively by Team 4.

The repository contains the application's implementation, supporting documentation, testing resources, and project deliverables.
