\# Lab 5 – Reflection



\### 1. What is static code analysis?



Static code analysis examines source code without executing

the program. It helps identify programming mistakes,

security concerns and coding-standard violations.



\### 2. What did you learn from Pylint?



Pylint helped identify code-quality issues such as mutable

default arguments, missing documentation, naming problems

and unnecessary global statements. It helped improve the

readability and maintainability of the program.



\### 3. What did you learn from Bandit?



Bandit helped identify potentially unsafe coding practices.

The analysis highlighted silent exception handling and

the use of a standard pseudo-random generator.



\### 4. What did you learn from Flake8?



Flake8 helped identify formatting problems such as incorrect

blank-line spacing, long lines and bare exception syntax.

It helped bring the code closer to PEP 8 standards.



\### 5. Why is static analysis important?



Static analysis helps developers identify potential problems

early, improve code quality and reduce maintenance effort.

It also encourages consistent coding practices.



\### 6. What was the overall outcome?



The original program received a Pylint score of 6.25/10,

two low-severity Bandit findings and ten Flake8 violations.



After making corrections, the program achieved a Pylint

score of 10.00/10, zero Bandit findings and zero Flake8

violations.



The program was also improved with passenger validation,

route checking and safer file handling.
